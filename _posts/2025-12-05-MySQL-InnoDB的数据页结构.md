## 页的简介

`页`是InnoDB管理存储空间的基本单位，一个页的大小一般是`16KB`。MySQL中有不同类型的页。存放我们表中记录的那种类型的页，官方称这种存放记录的页为`索引（INDEX）页`。

## 索引页

一个索引页可以被大致划分为7个部分，分别是

- File Header，表示页的一些通用信息，占固定的38字节。
- Page Header，表示索引页专有的一些信息，占固定的56个字节。
- Infimum + Supremum，两个虚拟的伪记录，分别表示页中的最小和最大记录，占固定的26个字节。
- User Records：真实存储我们插入的记录的部分，大小不固定。
- Free Space：页中尚未使用的部分，大小不确定。
- Page Directory：页中的某些记录相对位置，也就是各个槽在页面中的地址偏移量，大小不固定，插入的记录越多，这个部分占用的空间越多。
- File Trailer：用于检验页是否完整的部分，占用固定的8个字节。

## 行记录在页中的存储

一开始生成页的时候没有`User Records`部分，当插入第一条数据后，才从`Free Space`中申请一个记录大小的空间划分到`User Records`部分用来存储。

### 记录头信息的秘密

- heap_no
表示当前记录在本页中的位置。
索引页中有两条自动创建的虚拟记录，这两个伪记录一个代表最小记录，heap_no为0，一个代表最大记录，heap_no为1。比较记录的大小就是比较主键的大小。

- record_type
表示当前记录的类型，0=普通记录，1=B+树非叶子节点记录，2=最小记录，3=最大记录

- delete_mask
标记该记录是否被删除，当记录被删除时，标记为1，并且从由`next_record组成的单链表`中移除。添加到一个`垃圾链表`中，当后续有新记录要插入的时候，可以复用该记录的空间。

- n_owned
索引页中的记录会分组，表示以该条记录为结尾的分组中有多少条记录。

- next_record
页内通过next_record组成一个按主键大小排序的单链表。

### Page Directory（页目录）

InnoDB的页目录制作过程是这样的：

1. 将所有正常的记录（包括最大和最小记录，不包括标记为已删除的记录）划分为几个组。
2. 每个组的最后一条记录（也就是组内最大的那条记录）的头信息中的`n_owned`属性表示该记录拥有多少条记录，也就是该组内共有几条记录。
3. 将每个组的最后一条记录的地址偏移量单独提取出来按顺序存储到靠近页的尾部的地方，这个地方就是页目录。页面目录中的这些地址偏移量被称为`槽`。

![7.png](/assets/images/7.png)

InnoDB的每个分组中的记录条数是有规定的：
- 对于最小记录所在的分组只能有 `1` 条记录
- 最大记录所在的分组拥有的记录条数只能在 `1~8` 条之间
- 剩余的分组中记录的条数范围只能在是 `4~8` 条之间。（当插入后组内记录数等于8时，就会开始分裂成两个组）

槽是有序数组，可以快速通过隔壁槽找到当前槽的组内主键值最小的记录。

在一个数据页中查找指定主键值的记录的过程分为两步：
1. 通过二分法确定该记录所在的槽，并找到该槽所在分组中主键值最小的那条记录。
2. 通过记录的`next_record`属性遍历该槽所在的组中的各个记录。

### Page Header（页面头部）（了解）

Page Header的部分，它是页结构的第二部分，这个部分占用固定的`56`个字节，专门存储各种状态信息

| 字段名 | 字节数 | 含义 |
|--------|--------|------|
| PAGE_N_DIR_SLOTS | 2 | 页目录中的槽数量 |
| PAGE_HEAP_TOP | 2 | 还未使用的空间最小地址，从该地址之后就是 Free Space |
| PAGE_N_HEAP | 2 | 本页中的记录数量（包括最小和最大记录以及标记为删除的记录） |
| PAGE_FREE | 2 | 第一个已标记为删除的记录地址（各个已删除记录通过 next_record 组成单链表，可被重用） |
| PAGE_GARBAGE | 2 | 已删除记录占用的字节数 |
| PAGE_LAST_INSERT | 2 | 最后插入记录的位置 |
| PAGE_DIRECTION | 2 | 记录插入的方向 |
| PAGE_N_DIRECTION | 2 | 一个方向连续插入的记录数量 |
| PAGE_N_RECS | 2 | 该页中记录的数量（不包括最小和最大记录以及被标记为删除的记录） |
| PAGE_MAX_TRX_ID | 8 | 修改当前页的最大事务 ID（仅在二级索引中定义） |
| PAGE_LEVEL | 2 | 当前页在 B+ 树中所处的层级 |
| PAGE_INDEX_ID | 8 | 索引 ID，表示当前页属于哪个索引 |
| PAGE_BTR_SEG_LEAF | 10 | B+ 树叶子段的头部信息（仅在 B+ 树 Root 页定义） |
| PAGE_BTR_SEG_TOP | 10 | B+ 树非叶子段的头部信息（仅在 B+ 树 Root 页定义） |

### File Header（文件头部）（了解）

File Header作为第一个组成部分，它描述了一些针对各种页都通用的一些信息，比方说这个页的编号是多少，它的上一个页、下一个页是谁等等。占用固定的`38`个字节。

| 名称 | 占用空间大小 | 描述 |
|------|--------------|------|
| FIL_PAGE_SPACE_OR_CHKSUM | 4字节 | 页的校验和（checksum 值） |
| FIL_PAGE_OFFSET | 4字节 | 页号 |
| FIL_PAGE_PREV | 4字节 | 上一个页的页号 |
| FIL_PAGE_NEXT | 4字节 | 下一个页的页号 |
| FIL_PAGE_LSN | 8字节 | 页面被最后修改时对应的日志序列号（Log Sequence Number, LSN） |
| FIL_PAGE_TYPE | 2字节 | 该页的类型 |
| FIL_PAGE_FILE_FLUSH_LSN | 8字节 | 仅在系统表空间的某些页中定义，表示文件至少被刷新到对应的 LSN |
| FIL_PAGE_ARCH_LOG_NO_OR_SPACE_ID | 4字节 | 页所属的表空间 |

- FIL_PAGE_PREV和FIL_PAGE_NEXT

FIL_PAGE_PREV和FIL_PAGE_NEXT就分别代表本页的上一个和下一个页的页号。
所有的数据页其实是一个双链表。
