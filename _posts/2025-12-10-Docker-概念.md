## Docker 镜像和容器

### 镜像

镜像不包含 **Linux 内核**，只包含 **用户态文件系统**（如 `/bin`、`/usr`、`/etc`、工具、库等）的定义和配置，没有动态数据。

Dockerfile 里每条指令（RUN / COPY / ADD / ENV / WORKDIR 等）在构建镜像时都会, 在上一层基础上执行操作（新增、修改、删除文件或设置环境变量等）。把这一步产生的文件系统变化 快照化，生成新的只读层（read-only layer）。

镜像叠加就是：在基础镜像之上不断新增只读层；容器运行时再加一个可写层，通过 OverlayFS 合并成最终文件系统。镜像层不能被修改，所有变更都写在容器层中。

**镜像增加/修改/删除文件的原理**

1. 增加文件
Dockerfile 中新增文件或拷贝文件 → 生成新层记录新增文件

2. 修改文件
Dockerfile 中修改已有文件 → 生成新层记录修改后的版本
OverlayFS 叠加时，新层覆盖底层文件

3. 删除文件
Dockerfile 中删除文件 → 新层创建 whiteout 标记隐藏底层文件
底层文件仍存在，但在最终镜像里看不到

### 容器

镜像（`Image`）和容器（`Container`）的关系，就像是面向对象程序设计中的`类`和`实例`一样。容器可以被`创建、启动、停止、删除、暂停`等。
容器的实质是进程，容器进程运行于属于自己的独立的`命名空间`，可以有自己的网络配置、进程空间等等。

每一个容器运行时，是以镜像为基础层，在其上创建一个当前容器的存储层(可写层)。容器存储层的生存周期和容器一样，容器消亡时，容器存储层也随之消亡。

**按照 Docker 最佳实践的要求，容器不应该向其存储层内写入任何数据**, 都应该使用`数据卷（Volume）`、或者`绑定宿主目录`

## 仓库

`Docker Registry`是一个集中的存储、分发镜像的服务。

一个`Docker Registry`中可以包含多个`仓库（Repository）`；每个仓库可以包含多个`标签（Tag）`；每个标签对应一个镜像。

### 公开 Docker Registry

最常使用的 Registry 公开服务是官方的[Docker Hub](https://hub.docker.com)，这也是默认的 Registry。

### 私有 Docker Registry

除了使用公开服务外，用户还可以在本地搭建私有 Docker Registry。Docker 官方提供了 Docker Registry 镜像，可以直接使用做为私有 Registry 服务。
