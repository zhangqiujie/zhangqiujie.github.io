# MySQL 单表查询访问方法（Access Method）

## 核心流程
SQL → 解析 → 优化器 → 执行计划 → 存储引擎 → 返回结果；本质：优化器选择最低成本访问路径（Access Method）

---

## 示例表（固定）
```sql
CREATE TABLE single_table (
id INT NOT NULL AUTO_INCREMENT,
key1 VARCHAR(100),
key2 INT,
key3 VARCHAR(100),
key_part1 VARCHAR(100),
key_part2 VARCHAR(100),
key_part3 VARCHAR(100),
common_field VARCHAR(100),
PRIMARY KEY(id),
KEY idx_key1(key1),
UNIQUE KEY idx_key2(key2),
KEY idx_key3(key3),
KEY idx_key_part(key_part1,key_part2,key_part3)
);
```

索引：PRIMARY=聚簇索引；idx_key1/idx_key3=普通二级索引；idx_key2=唯一二级索引；idx_key_part=联合索引

---

# 访问方法总览（EXPLAIN type）
`const > ref > ref_or_null > range > index > all`

---

# const（最优）

定义：主键/唯一索引等值命中1条记录

示例：
```sql
SELECT * FROM single_table WHERE id = 1438;
```

```sql
SELECT * FROM single_table WHERE key2 = 3841;
```

流程：B+Tree定位 →（二级索引则）回表 → 返回1行

特点：最多1条记录；O(logN)；极快

联合索引条件：必须全列等值才const，如`key_part1='a' AND key_part2='b' AND key_part3='c'`

注意：`UNIQUE + NULL`不算const（NULL可重复）

面试点：唯一性保证 + B+Tree定位 → 为什么快

---

# ref（常用）

定义：普通二级索引等值查询

示例：
```sql
SELECT * FROM single_table WHERE key1 = 'abc';
```

流程：idx_key1定位多条 → 回表 → 返回结果

特点：可能多行；性能取决于命中行数

联合索引示例：
```sql
SELECT * FROM single_table WHERE key_part1 = 'god like';
SELECT * FROM single_table WHERE key_part1 = 'god like' AND key_part2 = 'legendary';
SELECT * FROM single_table WHERE key_part1 = 'god like' AND key_part2 = 'legendary' AND key_part3 = 'penta kill';
```

失效示例：
```sql
SELECT * FROM single_table WHERE key_part1='god like' AND key_part2 > 'legendary';
```

特点：满足最左前缀 + 等值才ref

风险：命中过多 → 回表爆炸 → 可能比all慢

---

# ref_or_null

示例：
```sql
SELECT * FROM single_table WHERE key1 = 'abc' OR key1 IS NULL;
```

流程：ref查abc + 扫NULL段 + 合并结果

特点：等值+NULL补集扫描

---

# range（重点）

示例：
```sql
SELECT * FROM single_table
WHERE key2 IN (1438, 6328)
   OR (key2 >= 38 AND key2 <= 79);
```

拆解区间：
- key2=1438 → [1438,1438]
- key2=6328 → [6328,6328]
- key2 BETWEEN 38 AND 79 → [38,79]

特点：多个区间扫描；本质B+Tree范围遍历

常见触发：
- `BETWEEN`
- `>`
- `<`
- `IN`
- `LIKE 'abc%'`

面试点：IN / BETWEEN / like前缀 → range

---

# index（扫索引）

示例：
```sql
SELECT key_part1, key_part2, key_part3
FROM single_table
WHERE key_part2 = 'abc';
```

原因：key_part2不满足最左前缀 → 不能ref/range定位

执行：扫描 idx_key_part 全部叶子节点 → 过滤条件 → 返回

特点：不回表 or 少回表；扫描整个二级索引

为什么比all快：
索引数据更小（只存索引列+主键）

面试点：index ≠ 用索引优化，而是“扫索引”

---

# all（最差）

示例（原文推导）：
```sql
SELECT * FROM single_table;
```

或：
```sql
SELECT * FROM single_table WHERE common_field = 'abc';
```

（common_field无索引）

流程：逐行扫描聚簇索引 → 判断条件 → 返回

特点：O(N)全表扫描

面试点：
- 小表 all 可能最快
- 大表 all 风险极高
- 索引失效 / 选择性差 / 回表太贵都会触发 all

---

# EXPLAIN核心
type字段 = 访问方法

```text
const / ref / range → 正常
index → 扫索引
all → 警惕
```

---

# 一页记忆版（面试速记）

- const：`id=1` / `unique=1` → 1行定位  
- ref：`idx_col='a'` → 多行  
- range：`> < between in like%` → 区间扫描  
- index：扫整个索引  
- all：扫整表  

---

# 本质一句话
MySQL优化器在做选择：用“点查（const/ref）”还是“范围（range）”还是“扫描（index/all）”，目标永远是最低IO成本

---

# 注意事项

## 二级索引 + 回表
查询一般只能利用单个二级索引：

```sql
SELECT * FROM single_table WHERE key1 = 'abc' AND key2 > 1000;
```

优化器会选择扫描行数最少的索引（通常等值>范围），假设选择`idx_key1`：

1. **索引定位**：用`key1='abc'`从`idx_key1` B+树找到索引记录（记录只包含索引列+主键）。
2. **回表**：根据主键到聚簇索引获取完整记录，再过滤`key2>1000`。

⚠️ 注意：步骤1用不到`key2>1000`，必须回表后才能过滤。

---

## range访问方法区间

索引列 + 常数用`= <=> IN NOT IN IS NULL IS NOT NULL > < >= <= BETWEEN != LIKE` → 可产生区间。

- LIKE：仅完整或前缀匹配可用索引  
- IN：等价于多个OR等值匹配  

### AND → 交集，OR → 并集

1. 每个搜索条件都可以使用到某个索引，优化器可以直接取到交集或者并集范围，到索引树中查询。

```sql
SELECT * FROM single_table WHERE key2 > 100 AND key2 > 200; -- range: (200,+∞)
SELECT * FROM single_table WHERE key2 > 100 OR key2 > 200;  -- range: (100,+∞)
```

2. 如果只有部分条件有索引：

在确定查询方式前，无法用索引的`AND`条件替换为TRUE：

```sql
SELECT * FROM single_table WHERE key2 > 100 AND common_field='abc';
-- 替换无用条件 → SELECT * FROM single_table WHERE key2 > 100;
```
可以用到key2索引。

`OR`条件也一样：

```sql
SELECT * FROM single_table WHERE key2>100 OR common_field='abc';
-- 替换后 → SELECT * FROM single_table WHERE TRUE → 扫全索引
```
变成全表扫描。**也就是说一个使用到索引的搜索条件和没有使用该索引的搜索条件使用OR连接起来后是无法使用该索引的。**

复杂条件示例：

```sql
SELECT * FROM single_table WHERE 
(key1>'xyz' AND key2=748) OR
(key1<'abc' AND key1>'lmn') OR
(key1 LIKE '%suf' AND key1>'zzz' AND (key2<8000 OR common_field='abc'));
```

- 使用`idx_key1` → 替换无索引条件为TRUE → `(key1>'xyz') OR (key1<'abc' AND key1>'lmn') OR (key1>'zzz')` → 化简 `(key1>'xyz')`  
- 使用`idx_key2` → 替换无索引条件 → 化简 `TRUE` → 扫全索引，成本高

---

## Index Merge（索引合并）

### Intersection（交集，AND）
```sql
SELECT * FROM single_table WHERE key1='a' AND key3='b';
```
- 分别扫描`idx_key1`和`idx_key3`  
- 求主键交集 → 回表  
- 优点：减少回表开销，适合单索引回表多的场景  
- 条件：二级索引列必须等值匹配（联合索引必须全列等值），主键列可范围匹配  
- Rowid Ordered Retrieval（ROR）：主键值有序 → 求交集O(n)

示例：
```sql
SELECT * FROM single_table WHERE key1='a' AND key_part1='a' AND key_part2='b' AND key_part3='c';
```

---

### Union（并集，OR）
```sql
SELECT * FROM single_table WHERE key1='a' OR key3='b';
```
- 各索引结果取并集 → 回表  
- 条件：索引列等值匹配，支持Intersection结果参与

### Sort-Union
- OR条件下各索引主键未排序 → 先对二级索引主键排序，再Union  
- 没有Sort-Intersection，因为Intersection适用结果集大，排序成本过高

---

## 索引合并注意事项
- 联合索引替代Intersection：
```sql
ALTER TABLE single_table DROP INDEX idx_key1, DROP INDEX idx_key3, ADD INDEX idx_key1_key3(key1,key3);
```
- 使用联合索引查询更快，无需多B+树扫描与合并  
- 注意单独对key3查询的业务场景需保留单列索引
