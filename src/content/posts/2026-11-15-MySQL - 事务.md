## 一、事务与 ACID

事务将一组数据库操作组织为一个逻辑工作单元。以转账为例，扣款与入账应共同成功或共同撤销。在 MySQL 中，常用的事务型存储引擎是 InnoDB。

- **原子性（Atomicity）**：事务中的操作作为整体提交或回滚，不能只保留其中一部分。
- **一致性（Consistency）**：事务执行前后，数据应满足既定的业务约束和数据库约束。例如转账的扣款额与入账额应相等；事务机制不能代替业务规则本身。
- **隔离性（Isolation）**：并发事务的中间结果按所选隔离级别彼此隔离。隔离级别不同，允许观察到的并发现象也不同。
- **持久性（Durability）**：事务提交后，其结果在故障恢复后仍应保留。

从生命周期看，事务会经历执行、提交或失败后回滚。教材中的五状态模型可帮助理解这个过程，但不对应 MySQL 中可逐项查询的事务状态。

## 二、开启、提交与回滚

```sql
BEGIN;
-- 或：START TRANSACTION;
UPDATE account SET balance = balance - 10 WHERE id = 1;
UPDATE account SET balance = balance + 10 WHERE id = 2;
COMMIT;
```

`BEGIN` 与 `START TRANSACTION` 都可显式开启事务；`COMMIT` 提交，`ROLLBACK` 撤销尚未提交的操作。例如第二次更新失败，应回滚整个转账。再次执行 `BEGIN` 或 `START TRANSACTION` 会先隐式提交当前事务，不能借此嵌套事务。

`START TRANSACTION` 还可指定 `READ ONLY`、`READ WRITE` 或 `WITH CONSISTENT SNAPSHOT`。后者用于在事务开始时建立一致性读快照，不会改变隔离级别；具体适用条件可查对应 MySQL 版本文档。

## 三、自动提交与隐式提交

MySQL 的 `autocommit` 默认开启。未显式开启事务时，每条执行成功的语句作为独立事务提交；可用 `SHOW VARIABLES LIKE 'autocommit';` 查看。将 `autocommit` 设为 `OFF` 后，`COMMIT` 或 `ROLLBACK` 结束当前事务，并立即开始下一个事务。

即使显式开启了事务，一些语句仍会触发**隐式提交**。例如多数定义或修改数据库对象的 DDL 语句会先提交当前事务，因此随后执行 `ROLLBACK` 不能撤销 DDL 之前的更新。`CREATE TEMPORARY TABLE` 和 `DROP TEMPORARY TABLE` 不会隐式提交，但这两条语句自身也不能通过回滚撤销；具体语句需查 MySQL 官方隐式提交清单。

## 四、保存点

保存点允许只撤销事务中的一部分操作：

```sql
BEGIN;
UPDATE account SET balance = balance - 10 WHERE id = 1;
SAVEPOINT before_credit;
UPDATE account SET balance = balance + 11 WHERE id = 2; -- 入账金额写错
ROLLBACK TO SAVEPOINT before_credit;
UPDATE account SET balance = balance + 10 WHERE id = 2; -- 更正后重新入账
COMMIT;
```

`ROLLBACK TO SAVEPOINT` 只回滚到指定位置，不结束事务。示例撤销错误入账后，仍需补做正确入账，再提交整个转账。若无法补做，应整体回滚。

## 五、Java 应用中的事务边界

在 JDBC 中，一组需要共同提交的 SQL 必须使用**同一个 `Connection`**。关闭自动提交后，全部成功才调用 `commit()`；发生异常时调用 `rollback()`，并在连接复用前恢复原有的自动提交状态。若扣款和入账分别使用两个独立连接，它们不会自动组成一个本地事务。

在 Spring 默认的代理式事务管理中，`@Transactional` 只拦截经过代理的调用；同类内部方法直接调用另一个带注解的方法，不会因此开启该方法声明的事务。默认情况下，未处理的 `RuntimeException` 或 `Error` 会触发回滚，受检异常默认不会；需要时可配置 `rollbackFor`。若异常在事务方法内部被捕获后正常返回，且事务未被标记为回滚，方法结束时通常会提交。

Spring 的事务上下文通常绑定当前线程，异步新线程不会自动继承原事务。隔离级别、MVCC、锁与死锁也直接影响事务行为，适合在后续专题展开。

## 面试考点与案例

1. **两条转账 SQL 都成功，为什么仍可能不满足一致性？** 事务负责将操作作为整体提交或回滚；扣款与入账金额、余额约束等仍需由业务逻辑或数据库约束正确表达。
2. **扣款和入账分别通过两个 JDBC `Connection` 执行，能靠一次 `commit()` 保证原子性吗？** 不能。本地事务由连接控制；两条 SQL 应使用同一连接，关闭自动提交，成功时提交，失败时回滚。
3. **`@Transactional` 方法抛出受检异常，或捕获运行时异常后正常返回，会自动回滚吗？** 默认不会。受检异常需要相应的 `rollbackFor` 规则；捕获异常后若仍需回滚，应让符合规则的异常向外传播或明确标记回滚，具体还要看事务此前是否已被标记为仅回滚。
4. **同类内部直接调用带 `@Transactional` 的方法，为什么注解可能不生效？** Spring 默认代理模式只拦截经过代理的调用；内部直接调用没有经过代理。
5. **`BEGIN` 后更新数据，再执行普通 `CREATE TABLE`，最后 `ROLLBACK`，更新能撤销吗？** 不能。建表语句会先隐式提交已有事务。
6. **再次执行 `BEGIN` 可以嵌套事务吗？保存点有何不同？** MySQL 会先提交已有事务，不能以此嵌套。保存点只允许在当前事务内局部回滚，`ROLLBACK TO SAVEPOINT` 不结束事务。
