# InnoDB 存储结构与行格式

## InnoDB 页简介
- InnoDB 将数据存储在磁盘页中
- 页大小：**16 KB**
- 磁盘与内存交互的最小单位：页
- 读取与刷盘：一次至少 16KB

---

## InnoDB 行格式
- 四种行格式
  - Compact
  - Redundant
  - Dynamic
  - Compressed
- 指定行格式语法：
  - CREATE TABLE ... ROW_FORMAT=xxx
  - ALTER TABLE ... ROW_FORMAT=xxx

---

## Compact 行格式
### 记录结构
- 由两部分组成：
  - 记录的额外信息
  - 记录的真实数据

### 1. 记录的额外信息
#### （1）变长字段长度列表
- 记录 VARCHAR、VARBINARY、TEXT 等变长列的实际字节数
- 倒序存储（列顺序相反）
- 需要记录长度的条件
  - 数据类型为变长
  - 字符集为变长字符集

##### 字节数规则
- M：最大字符数
- W：字符集最大字节数（ascii=1, gbk=2, utf8=3）
- L：实际字节数
- 存储规则：
  - 若 M × W <= 255 → 用 1 字节表示 L
  - 若 M × W > 255
    - L <= 127 → 1 字节
    - L > 127 → 2 字节
- 无变长列 → 此部分不存在

#### （2）NULL 值列表
- 只存储允许为 NULL 的列
- 位图逆序存储
  - 1 = NULL
  - 0 = 非 NULL
- 字节对齐（不足补 0）
- 无可为 NULL 的列 → 不存在

#### （3）记录头信息
- delete_mask（1bit）：是否被删除
- min_rec_mask（1bit）：非叶子节点最小记录标记
- n_owned（4bit）：当前记录拥有的记录数
- heap_no（13bit）：堆中位置
- record_type（3bit）：记录类型（普通/最小/最大/B+树内部）
- next_record（16bit）：下一条记录相对位置

---

### 2. 记录的真实数据
- 存储所有非 NULL 列的值
- 包含隐藏列：

| 列名 | 必须 | 大小 | 描述 |
|------|------|------|------|
| DB_ROW_ID | 否 | 6B | 行 ID（无主键时才有） |
| DB_TRX_ID | 是 | 6B | 事务 ID |
| DB_ROLL_PTR | 是 | 7B | 回滚指针 |

#### 主键生成策略
1. 使用用户定义的主键
2. 无主键则选择一个唯一键
3. 若都没有 → 自动添加 DB_ROW_ID

---

## CHAR(M) 存储规则
- 固定长度字符集（ascii）：不记录变长长度
- 变长字符集（utf8/gkb）：需要记录实际字节数

---

## 行溢出数据
### MySQL 单行最大限制：65535 字节（Server 层）
- 不包括 BLOB/TEXT 实际数据
- 每个 VARCHAR 存储结构：
  - 实际数据 L
  - 长度字节（1~2B）
  - NULL 标识（有时需要）

#### VARCHAR(M) 最大值
- 若可 NULL → 最大实际数据约为 65532 字节
- M 的最大值：
  - ascii：65532 字符
  - utf8：~~21844 字符（≈65532/3）

---

## 页大小 VS 行最大长度冲突
- 行逻辑上限：65535 字节（Server）
- 页物理大小：16384 字节（InnoDB）
- InnoDB 溢出机制：
  1. 尝试把完整行放进页
  2. 如果放不下 → 对“大列”产生溢出
     - Compact：保留前 768 字节 + 20 字节指针
     - 剩余数据存放到溢出页
- BLOB/TEXT 也使用溢出页存储

---

## Dynamic 与 Compressed 行格式
### Dynamic 行格式
- 默认行格式
- 行溢出时：**真实数据不放 768 字节前缀，直接全部放溢出页**
- 主记录中只保存指针结构

### Compressed 行格式
- 在 Dynamic 基础上：
  - 页数据会压缩存储
- 目标：减少磁盘占用
