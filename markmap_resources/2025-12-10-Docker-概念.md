# Docker 镜像和容器

## 镜像
- 不包含 Linux 内核
- 包含用户态文件系统（/bin, /usr, /etc, 工具, 库等）
- 没有动态数据
- 构建过程
  - Dockerfile 每条指令（RUN, COPY, ADD, ENV, WORKDIR 等）在上一层基础上执行
  - 生成只读层（read-only layer）
  - 镜像层叠加形成最终镜像
  - 容器运行时加可写层，通过 OverlayFS 合并
- 镜像层不能修改，所有变更写在容器层
- 文件操作原理
  - 增加文件：新增文件或拷贝 → 新层记录新增
  - 修改文件：修改已有文件 → 新层记录修改后的版本 → OverlayFS 覆盖底层文件
  - 删除文件：删除文件 → 新层 whiteout 标记 → 底层文件仍存在，但最终镜像看不到

## 容器
- 镜像 vs 容器：类 vs 实例
- 容器操作：创建、启动、停止、删除、暂停
- 容器实质：进程
  - 运行在独立命名空间
  - 独立网络配置、进程空间等
- 存储层
  - 容器基于镜像层创建可写层
  - 存储层生命周期与容器一致
- 最佳实践：容器不应向存储层写数据
  - 使用数据卷（Volume）或绑定宿主目录

## 仓库
- Docker Registry：集中存储和分发镜像服务
- Registry 构成
  - 多个仓库（Repository）
  - 每个仓库有多个标签（Tag）
  - 每个标签对应一个镜像
- 公开 Registry
  - 官方 Docker Hub（默认 Registry）
- 私有 Registry
  - 可在本地搭建
  - 官方提供 Docker Registry 镜像作为私有服务
